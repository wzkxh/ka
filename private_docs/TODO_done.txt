Engine: one formatting engine works on text and writes into a 64-character stack buffer.

Version 7.1 adds -e, -k and -c to kota.py. The 223 .ko tests and a new test of the options pass in the emulator, but I couldn't test actually launching an .exe here, since this sandbox isn't Windows.

How the options behave:

-e file.ko: compiles, runs the .exe and deletes it. The exit code of kota.py is the exit code of your program.
-k: with -e or -c, keeps the .exe and prints kept NAME on stderr, so the program's own output stays alone on stdout. -k on its own is a usage error.
-c "text": compiles the text itself, runs it and deletes the .exe, like python -c. I did it internally with no temp .ko file. Errors are named <command>.
Where the .exe goes:
Run and delete: it is a file in the temp directory, so an existing program.exe next to your source is never overwritten or deleted.
With -k: it stays next to the source, or becomes yyyymmdd_HHMMSS.exe in the current directory for -c.
With -o NAME: it uses that name, and it is still deleted after the run unless you also give -k.
Errors: a compile error runs nothing and leaves no file. A source file together with -c is a usage error.
Other systems: on non-Windows it prints cannot run a Windows .exe on this system and exits with 1, without trying Wine.
